# Entregas do PulseVida

- [x] **Integração real e dados persistentes:** O site deve executar em Preview, falar com backend e banco gerenciado do projeto e persistir dados entre acessos/perfis. Não tratar o protótipo HTML com armazenamento local como integração real. Usar migrações e instruções necessárias para executar o backend. — Express e MySQL gerenciado conectados; `/healthz` retornou `200` com `database: connected`; migração versionada e instruções estão no README.
- [x] **Autenticação e permissões por perfil:** Pacientes, profissionais de saúde e administradores devem entrar em suas áreas próprias. Cadastro público deve criar apenas paciente; ações e endpoints de cada perfil precisam ser autorizados pelo backend. Os registros clínicos acessados por paciente devem pertencer à conta autenticada. — Conta administrativa inicial autenticou; sessão foi revogada no logout; endpoint clínico testado sem privilégio respondeu `403`; autorização e filtros por paciente estão no backend. Não foram criadas contas fictícias de equipe/paciente no banco compartilhado.
- [x] **Área do paciente:** Permitir consultar resumo e histórico de aferições/atendimentos, registrar aferição e criar solicitação de consulta; mostrar o status atualizado das consultas vinculadas à conta. — Painel e endpoints persistentes implementados para aferições, consultas, perfil e histórico.
- [x] **Área profissional:** Mostrar fila de agendamentos/solicitações e aferições disponíveis para acompanhamento autorizado; permitir confirmar solicitações e registrar atendimento/observações com vínculo ao paciente correto. As alterações devem ser persistidas e refletidas nos outros perfis. — Fila, transições de status e registro transacional do atendimento implementados; não foram inseridos registros clínicos artificiais para teste no banco compartilhado.
- [x] **Área administrativa:** Permitir consultar contas por perfil e agendamentos, criar acessos profissionais de forma controlada e administrar solicitações sem exposição de senha ou dados que não sejam necessários. — Gestão de perfis/agendamentos implementada; CPF e Cartão SUS foram removidos das respostas e consultas administrativas; e-mail é limitado ao fluxo profissional.
- [x] **Interface responsiva para smartphone:** Disponibilizar os mesmos fluxos essenciais como site responsivo, com navegação e formulários utilizáveis em telas pequenas. Não criar app nativo de loja. — Media queries para desktop/tablet/smartphone; tela de login conferida em viewport 390×844.
- [x] **Preservação do projeto original:** Reaproveitar sua marca, assets e funcionalidades pertinentes (incluindo pesquisa/feedback e páginas públicas do projeto), organizando os arquivos sem deixar de servir as telas por perfil. — Marca e imagens selecionadas reaproveitadas; páginas públicas, unidades, orientações e feedbacks no manifesto; 10 páginas responderam `200`.
- [x] **Preparação para GitHub:** Incluir estrutura versionável, arquivo `.gitignore`, dependências/lockfile, exemplo de variáveis sem segredos, documentação de setup e instruções de implantação. Não publicar o site nem fazer push/conectar ao GitHub do usuário sem autorização separada. — Arquivos presentes; deploy de contêiner preparado no projeto Manus; nenhum envio ao GitHub do usuário nem publicação do site foi feito.
- [x] **Segurança e escopo acadêmico:** Não incluir segredos no repositório, demonstrar dados fictícios e informar que a aplicação acadêmica não é certificação clínica/LGPD para uso com dados reais. — Credencial de bootstrap removida da configuração; repositório não contém `.env`; README alerta sobre uso acadêmico, dados fictícios e ausência de validação clínica/regulatória. Pesquisa pública limitada a cinco tentativas por IP/15 min; datas alinhadas a `America/Sao_Paulo`.

## Limite de validação da demonstração

A saúde do servidor/banco, as rotas, o login e a autorização administrativa foram verificados sem criar pacientes, profissionais ou dados clínicos de demonstração. Para apresentar o fluxo entre perfis, siga o roteiro do README e cadastre contas/dados fictícios pela própria interface.
